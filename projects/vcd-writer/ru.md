Value Change Dump (VCD) — текстовый формат, в котором симуляторы аппаратуры записывают, как сигналы меняются во времени; программы просмотра вроде GTKWave рисуют его в виде временных диаграмм. **vcd-writer** пишет такие файлы из кода на C++: симулятор, эмулятор или тестовое окружение регистрирует переменные во вложенных областях видимости и сообщает об их изменениях, а библиотека выдаёт VCD-файл, который откроет любой просмотрщик временных диаграмм.

Начиналась она в 2017 году как порт Python-библиотеки [pyvcd](https://github.com/SanDisk-Open-Source/pyvcd), а в 2026-м превратилась в полноценную современную библиотеку.

## Что внутри

- **Стандарт, проверенный пункт за пунктом.** VCD с четырёхзначной логикой из IEEE 1364-2005 §18.2: заголовок (`$date`, `$version`, `$timescale`, `$comment`), вложенные области видимости, все 18 типов переменных, скалярные, векторные, вещественные и строковые значения, `$dumpvars`, `$dumpoff` / `$dumpon`. В README есть таблица: что поддерживается, а что нет.
- **Ни одного выделения памяти на изменение.** Значения пишутся в выходной буфер на 64 КиБ; бенчмарк лежит прямо в репозитории.
- **Проверки без побочных эффектов.** Имена, размеры, значения и дата проверяются до того, как что-либо изменится, поэтому неудачный вызов не оставляет в файле следов; метка времени из прошлого приводит к исключению.
- **Детерминированный вывод.** Файл получается побайтно одинаковым на любой платформе.
- **Чистый интерфейс.** Внутреннее состояние спрятано за pimpl; сторонних зависимостей нет.

## Инженерная часть

- CI на Linux, Windows и macOS: модульные тесты на GoogleTest и побайтовое сравнение с эталонным файлом; отдельная задача на Linux гоняет их под AddressSanitizer и UndefinedBehaviorSanitizer.
- Каждый коммит, прошедший CI, получает тег семантической версии и GitHub Release с собранными библиотеками.
- В CMake-проект библиотека подключается через `CPMAddPackage`; есть и сборка обычным Makefile.
- В README — сравнение по возможностям с pyvcd и cpp-vcd-tracer.

## Почему это важно

На небольшой библиотеке хорошо видно весь инженерный цикл: внимательно прочитанный стандарт, API, которым трудно воспользоваться неправильно, измеренная производительность и релизный процесс без ручных шагов.
