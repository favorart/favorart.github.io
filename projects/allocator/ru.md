Курсовой проект 2015 года (Техносфера, Mail.Ru Group и МГУ имени М. В. Ломоносова): аллокатор памяти, который сам управляет одной фиксированной ареной, а не вызывает системный `malloc`. В 2026 году код прошёл ревью: ошибки исправлены, у проекта появились настоящие тесты, CI и релизы.

## Как это устроено

- **Без лишней памяти.** Аллокатор раздаёт блоки из заранее выделенного буфера, а его собственные служебные данные — двусвязный список дескрипторов блоков, упорядоченный по адресам, — живут в том же буфере: они плотно, без зазоров, упакованы с его конца. Выделение ищет первый подходящий промежуток, проходя по списку, — O(число блоков); освобождение работает за O(1).
- **Дефрагментация.** После множества выделений и освобождений свободное место дробится на мелкие куски. `defrag()` за один проход сдвигает живые блоки вплотную друг к другу, и свободное место снова становится одной непрерывной областью; `realloc()` увеличивает или уменьшает блок без переноса, если хватает места.
- **Умный указатель.** Перемещение блоков сломало бы сырые указатели, поэтому пользователь работает через класс `Pointer`. Он запоминает ячейку дескриптора и уникальный номер блока и снова находит блок после переезда; указатель на освобождённый блок возвращает `nullptr`.

## Инженерная часть

- На ревью 2026 года старые тесты запустили под AddressSanitizer и UndefinedBehaviorSanitizer и нашли десять ошибок — от записи за пределы буфера до указателя, который находил чужой блок; на каждое исправление есть регрессионный тест.
- Тесты на GoogleTest покрывают весь публичный API, а рандомизированный стресс-тест сверяет каждый живой блок с моделью байт за байтом.
- CI собирает проект компиляторами GCC и Clang на Linux (в том числе с санитайзерами), MSVC на Windows и Apple Clang на macOS; предупреждения считаются ошибками.
- В README есть бенчмарк против `malloc`/`free`, который честно показывает цену: выделение проходит по списку и намного медленнее `malloc`, а сжатие — один проход `memmove`.
- Каждый пуш в `master`, прошедший CI, получает тег версии и GitHub Release с заголовочным файлом и статической библиотекой для Linux, Windows и macOS.

## Почему это важно

Собственные аллокаторы — один из главных инструментов оптимизации в C++: меньше системных вызовов, лучше локальность данных и предсказуемый расход памяти. Этот проект показывает механику изнутри — и цену перемещения объектов в памяти.
